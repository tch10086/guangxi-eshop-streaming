## 二、给 AI 的任务描述（从这里开始复制）

### 角色

你是有 5 年经验的大数据开发工程师兼技术文档写手。你要独立完成《【课程名】》的结课项目：**从零搭建环境、写完全部代码、跑出真实数据、写 6 章结课报告、按规范打包**。全程不许编造运行结果，报告里的每一个数字都必须来自真实执行。

### 一、先读材料，复述要求

依次读取并解析这 4 份材料（路径见变量表）：

1. `【作业要求文件】` —— 交付物、命名规则、截止时间、提交方式；
2. `【报告模板】` —— 章节骨架、封面字段、目录域、正文格式、红色提示文字；
3. `【案例 PPT】` —— 逐页提取文字与代码截图，梳理出系统模块、指标口径、技术栈、数据库/中间件参数；
4. `【撰写规范】`（.doc 格式，先用 Word COM 转 docx 再读）—— 页边距、字号、行距、页码、图表题注、层次编号、参考文献格式。

读完后先输出一份**不超过 30 行的理解摘要**：要做什么系统、分几个模块、报告写几章、交付什么、有哪些格式硬要求。确认无误再动手。

### 二、阶段一：环境核查与补齐

1. 登录虚拟机，盘点现状：`jps`、`ss -lntp`、`ls /opt/module`、`spark-submit --version`、`mysql -uroot -p -e "show databases;"`、`pip list`。
2. 对照案例 PPT 的组件清单，列出「已具备 / 缺失」两栏，缺什么补什么。**先用一条命令验证，再决定是否安装**，不要盲装。
3. 本项目典型缺口：
   - **Redis**：`yum install -y gcc` → 编译安装（`make && make PREFIX=... install`）→ 改 `bind`、`daemonize`、`appendonly` → `pip install redis`；
   - **Kafka Topic**：`--partitions 3 --replication-factor 1`（⚠️ 单机只能 1 副本，PPT 里的 2 副本是双 Broker 场景）；
   - **MySQL 库表**：建库 + 建表脚本落到 `sql/`，字符集 `utf8mb4`；
   - **Spark 连接器**：确认 `spark-sql-kafka-0-10`、`kafka-clients` 在 `$SPARK_HOME/jars`，MySQL 驱动用 `--jars` 传。
4. 启动顺序固定为：`MySQL → ZooKeeper → Kafka`，每步用端口验证，不要凭感觉 sleep。

### 三、阶段二：写代码（5 个模块）

目录结构（放到 `【项目根目录】`）：

```
项目名/
├── src/producer/    Simulator_Data.py  KafkaProducer.py
├── src/analysis/    Std_Analysis.py  StreamingRecommend.py  Off_Analysis.py
├── src/model/       ALSModeling.py
├── src/utils/       Config.py  MySQLUtil.py  RedisUtil.py  PrettyPrint.py
├── sql/             edu_mysql_ddl.sql
├── web/             接口服务
├── dashboard/       大屏页面（+ 本地 echarts.min.js）
├── scripts/         安装/启动/逐模块运行脚本
└── 报告输出目录
```

硬性技术要点（直接照做，能省一半调试时间）：

1. **造数要可学**：给每道题分配科目与难度、每个学生分配能力值与擅长科目，`得分 = f(能力 - 难度) + 噪声`，否则 ALS 学不到规律。
2. **流式聚合写在 `foreachBatch` 里**：把微批当普通 DataFrame 做 groupBy，不要直接对无界流 groupBy（会要求 complete 模式、状态无限增长）。
3. **`checkpointLocation` 必须写 `file:///绝对路径`**：不写协议前缀会被当成 HDFS 路径，直接 `Connection refused`。
4. **`read.jdbc` 的 `url` 是必填位置参数**：`spark.read.jdbc(url=..., table=..., properties=...)`。
5. **入口脚本统一加 `sys.path.insert(0, src 目录)`**：否则 `No module named 'utils'`。
6. **中文表格自己对齐**：Spark `show()` 按字符数补空格，中文会错位；写一个按 `east_asian_width` 计算宽度的打印函数。
7. **每个入口脚本都要有 `--start latest|earliest` 参数**，方便回放历史数据取证。
8. **流任务要容错**：Redis 没数据时跳过并提示，不抛异常。

### 四、阶段三：跑真实数据并取证

按顺序执行，每一步都要留下可引用的事实：

1. 生产 N 条数据 → `kafka-run-class GetOffsetShell` 记录分区 offset；
2. 起实时分析流 → 跑到一个「数据量适中」的批次（约 100–300 条），把该批次控制台输出原样存成 txt；
3. 训练 ALS → 记录 `样本数 / 稀疏度 / RMSE / 写入 Redis 的学生数`；
4. 起实时推荐流 + 再产一批数据 → 记录推荐总条数、覆盖学生数；
5. 跑离线分析 → 记录两张结果表的数据；
6. 起接口 → 记录 `/api/health`、`/api/edu_data` 的返回码与关键字段。

⚠️ 每一步的 txt 输出都会成为报告插图的原始素材，**不要手写、不要改数字**。

### 五、阶段四：大屏

- 方案 A（ECharts，推荐）：Flask 提供 `/api/edu_data`（指标卡 + 2 张聚合图 + Top10 + 最近 N 条流水），页面 3 秒轮询；ECharts 用本地 `echarts.min.js`，避免断网白屏。
- 方案 B（FineBI）：按 PPT 步骤装 5.1、配 MySQL 数据连接、建业务包、做折线图 + 柱状图。
- 要求：1600×900 下完整显示，深色科技风，指标卡在顶部，图表分区清晰，用 headless 浏览器截图验证（`msedge --headless=new --screenshot=... --window-size=1600,900 --virtual-time-budget=12000`）。

### 六、阶段五：写报告（重点，决定分数）

**结构**：严格按模板 6 章，一级标题自动编号（模板 Heading 样式已带多级编号，正文里**不要手写章节号**）。

| 章 | 内容 | 字数 | 必备素材 |
|---|---|---|---|
| 1 项目概述 | 背景（行业痛点 + 两个具体问题）、目标（6–7 条分点）、技术栈（表格 + 组件分工） | 1700 | 表：技术栈 |
| 2 需求分析 | 业务需求（数据从哪来、给谁用）、功能需求（6 条）、非功能（实时性/持久化/稳定性/可视化/资源） | 2200 | — |
| 3 系统设计 | 分层架构 + 数据流走向、8 张表设计、Kafka/Redis 参数 | 1800 | 图：架构图；表：表清单/核心表/离线表/中间件参数 |
| 4 系统实现与测试 | 按 7 个小节写（结构、生产、实时分析、模型、推荐、离线、可视化），每节配截图 + 关键数字；最后测试表 | 2600 | 图 9 张、表 2 张 |
| 5 遇到的问题与解决 | 4 个真实问题，按「现象→原因→解决」三段式 | 1600 | — |
| 6 总结与展望 | 完成情况、Spark 收获、实时 vs 离线对比、业务价值；局限 4 条、改进 4 条 | 1500 | — |

**排版（按《撰写规范》，用 python-docx 直接写 XML）**：

- 正文：宋体小四（12pt）、首行缩进 2 字符（0.85cm）、两端对齐、单倍行距；
- 标题：一级/二级 16pt 加粗，三级 14pt 加粗，每章 `page_break_before`；
- 图：居中，宽度 9–15cm，**图题在图下**、居中、五号加粗；
- 表：**三线表**（上下框线 + 表头下线，无竖线），**表题在表上**、居中、五号加粗，单元格 9.5pt，`cantSplit` 防跨页；
- 页码：只给正文节加居中 `PAGE` 域（模板原页脚是文本框里的域，导出 PDF 后页码会全部变成 1，必须重建）；
- 目录：模板里是 `TOC \o "1-3"` 域，最后用 Word COM `TablesOfContents(1).Update()` 更新；
- **模板里的红色提示文字必须全部删除**，一个 `FF0000` 的 run 都不能留。

**生成方式**：不要手工拼 Word。写 `content.py`（把每段文字、每张图、每张表作为数据块）+ `make_report.py`（渲染器），改文字只需改 `content.py`，重跑即可。

### 十、已知坑（照这个躲）

| 现象 | 原因 | 解法 |
|---|---|---|
| Kafka 启动即退出，`NodeExists /brokers/ids/0` | 非正常关机，ZK 残留注册 | 先重启 ZK，确认 `ls /brokers/ids` 为空再起 Kafka |
| `Connection refused`（Hadoop ipc.Client） | checkpoint 路径被当 HDFS | 写成 `file:///...` |
| `ModuleNotFoundError: No module named 'utils'` | 脚本目录不在 sys.path | 入口处 `sys.path.insert(0, src)` |
| `jdbc() missing 1 required positional argument` | 漏了 url 位置参数 | `read.jdbc(url=..., table=..., properties=...)` |
| 中文表格竖线错位 | `show()` 按字符数补空格 | 自写按显示宽度对齐的打印函数 |
| PDF 里页码全是 1 | 页脚域在文本框里，导出失效 | 重建页脚为普通居中 `PAGE` 域 |
| `Current batch is falling behind` | 单批处理超时 | 调小 `shuffle.partitions`、加 `trigger` 间隔，或忽略（会自动追赶） |
| 推荐结果为空 | 模型没训练 / Redis 没起 | 先跑 ALS，再起推荐流；入口打印 Redis 状态 |
